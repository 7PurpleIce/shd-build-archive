## Публикация и откат

Пока изменения находятся в отдельной ветке, опубликованный сайт работает на исходной версии. Закрытие pull request без слияния полностью отменяет предложенное обновление.

Рекомендуемый способ публикации — **Squash and merge**, чтобы весь рефакторинг оказался одним коммитом в `main`. После слияния GitHub Pages автоматически проверит, соберёт и опубликует сайт.

Если после публикации обнаружится проблема, используйте **Revert** у слитого pull request и слейте созданный обратный PR. Альтернатива из чистой рабочей копии:

```sh
git switch main
git pull --ff-only
git revert <SHA-коммита-Squash-and-merge>
git push origin main
```

GitHub Pages опубликует обратное изменение. Не используйте reset/force push: они могут потерять более поздние изменения. Резервная ветка сохраняет точный исходный код для сравнения. Откат кода не откатывает записи билдов в Supabase; этот рефакторинг не требует миграций базы.
